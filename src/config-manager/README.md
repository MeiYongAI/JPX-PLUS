# Configuration management

From 2026.11.08.12 the native-format settings and config library use the JPX-only shared storage facade backed by GM values. Primary and alt access one authoritative store; world suffixes retain their meaning. Native site storage remains a migration backup. See [sharing design and limitations](../../docs/alt-shared-data-2026-11-08.md). Edit src/shared-data.js and src/shared-ui.js, then use the existing build command.

The distributed userscript remains `JPX-PLUS.user.js`. These sources are embedded into its marked section by:

```powershell
node scripts/build-config-manager.cjs
```

Edit these modules, then rebuild. Do not hand-edit the generated block in the userscript.

Persona/set bindings live in library metadata, outside native JPX configs. In My configs, choose More → Bind loadout, then a world, persona and equipment set. A config can bind to multiple combinations; replacing an existing assignment asks for confirmation. Unbinding keeps the current rules. An unbound set keeps the last applied config. Manual application remains in effect until a different combination is confirmed. Saved edits take effect on the next matching switch, unless they introduce custom code: rebind that revision to approve it.

The bindings.js module reads native persona/set controls and shares the existing deduplicated, read-only character lookup when needed. HVUT completion is detected from its P/E progress indicator and world-specific cache; intermediate persona writes are ignored. There is no polling, battle-loop archive scan, or combat/puzzle lookup. Original JPX exports and imported rule structures do not gain binding fields. Chrome tests use isolated offline fixtures for native reloads, HVUT AJAX completion, stale observations, write rollback, both worlds and responsive dialogs; they do not claim a live game switch was performed.

Local configs default to type sorting, with name, update time and manual order available. Compact tags derive from populated rule groups, including multi-mode files; style and scene filters must match the same group. Clicking a tag filters the list, and search combines words from names and tags. Manual order reuses the statistics drag helper, also supports keyboard/menu movement, and persists only the library array order without changing rule revisions, applied snapshots or native exports. Sorting a filtered list leaves hidden entries in place. The selected sort is a separate local UI preference.

The store and Shared reuse the same tags. Tag colors use stable category IDs for style, world, scene, config type and element, with shared light/dark palettes; they do not depend on translated labels or config names. Optional `modes` metadata in the approved catalog supports full-file classification and search without downloading each snapshot. Older indexes remain readable; a full-file entry without mode metadata shows its known type and world until updated. Catalog metadata is generated from approved rules and is not added to the exported configuration.

| Source | Responsibility |
| --- | --- |
| `library.js` | Local archive, revisions, migration, applied snapshots and validation |
| `manager.js` | Management UI, detached rule editor, explicit application and cross-tab synchronization |
| `bindings.js` | World/persona/set detection and transactional application of bound configs |
| `store.js` | Existing GitHub service, authentication and embedded store UI |
| `manager.css` | Compact responsive layout using the existing theme tokens |
| `en.json` | English UI strings; other languages stay in the five external packs |

The native `jpx_cfgBattle` / `jpx_cfgBattle_isekai` structures remain the execution format. The library uses `jpx_configLibrary_v1`. Saving an archived configuration never applies it. Applying a single-mode entry selects that exact ruleset immediately, independently of detected equipment and battle type; the library's optional `active[world]` and applied snapshot `mode` retain this selection across reloads. Applying a complete native configuration clears the fixed-mode selection and uses the original automatic group routing. A multi-mode source stays one entry; its editor opens one group at a time. Explicit PLUS element choices stay under the mode's `jpxPlusExecution`, not in the detected spell-damage cache. Native exports do not include the library's selection state. Existing installations without a selection retain the original mode routing.

Native migration preserves an absent `smartDebuff.targetCount`: the battle runner already defaults it to 3. Assigning `undefined` during migration made valid older archives fail the strict applied-snapshot JSON validation, even when the affected group was not the current battle mode. `tests/jpx_battle_import_regression.test.cjs` exercises actual file selection and application in both worlds and in lobby/battle contexts. Set `JPX_CONFIG_REPRO` to an external config path to include a reporter's original file without copying it into the repository. Its routing probe verifies that steady-state mode lookup performs no archive reads or JSON serialization; this is not a live network-latency measurement.

The standalone Config Store is retired. The configuration-only migration bridge remains compatible with previously installed copies; it does not transfer tokens or delete source data. The integrated store signs in separately. Local configurations remain usable when game lookups are unavailable.

Local archive reads and writes belong to `library.js`; the embedded store no longer includes the retired backpack CRUD service or needs `GM_listValues`. Catalog ordering is reused across search/filter edits and recomputed only when the ordering changes or a fresh catalog is loaded.

Native storage is backed up to `<native-key>:configManagerBackup` before the first managed application. Library migration snapshots the previous raw library to `jpx_configLibrary_v1:backup`. Malformed data is not overwritten. Apply signals pause and update the relevant running battle tab; the user explicitly resumes battle.

Initial library entries come only from stored native modes containing support, attack, or key-binding rules. Untouched empty/default placeholders from earlier builds are hidden without deleting their data; manually saved drafts remain available. The detected equipment style is marked on matching list entries, independently of the selected ruleset. Success feedback dismisses after four seconds.

The local list filters by world, style, battle and type, with shared-world copies included under either world. Sorting supports type, name, update time and manual order, and is reused until the archive or sort changes. Search, filters, sort and scroll survive visits to the editor and store; mobile filters fold beside search using the existing store controls. The row menu offers a small Rename dialog with Enter/Escape support. Renaming checks the displayed revision, writes only library metadata, and advances matching applied revisions without concealing already-unapplied rule edits. It never applies a configuration or changes the native export format.

The general-settings battle export opens a native modal with In use, Full config and Choose rules. In use follows the actual execution mode, including explicit applied selections and General fallback, and exports only that group's rules; an unknown lobby style never invents an active group. Full config preserves the complete existing native export. Choose rules uses two linked dropdowns for style and battle scene and exports only the version and chosen mode key, so importing it cannot overwrite unrelated modes or panel settings. Export selection is detached from live data, needs no requests, supports keyboard cancellation/focus restoration and leaves native config storage unchanged. Statistics export and per-entry archive exports retain their existing behavior.

Validated archives and application comparisons are reused until their storage changes; every public library read still returns an independent copy. Unchanged list refreshes keep the existing rows, scroll and focus. Complete collapsed rule forms are built on first expansion and then reused; legacy records needing render-time normalization retain their original eager path before the history baseline. Disclosure keeps the summary in place, respects reduced motion, and avoids bulk height animations. The manager's low-specificity control defaults preserve native rule buttons and six-dot drag handles. On mobile, the settings-header Back handles nested configuration and store pages, including unsaved-rule prompts, with no duplicate inner Back.

Equipment-family observations are cached separately by world and persona for one minute. A non-combat management view without fresh evidence automatically reads the current world's character and equipment pages with deduplicated GET requests, without navigating. If equipment metadata is external, it also reads the equipment page's same-origin, same-world `dynjs/.../equip-ID.js` resource and parses only its JSON assignment; fetched scripts are never executed. Battle and puzzle pages never request these inaccessible pages; live battle skills and available attribute evidence are used instead. Battle responses, failed lookups, changed-persona results and results arriving after combat begins cannot populate the observation cache, including while external metadata is loading. Configuration data is never changed by detection.

Verification: run `npm run check` and `npm test` from the repository root. Tests use isolated browser profiles and mocked transport; they do not access a real battle, account or installed userscript storage. `npm run screenshots` captures the actual renderers with offline sample content. See [Development](../../docs/development.md) for setup.

Store discovery uses catalog metadata without fetching every configuration. Search matches all entered words across titles, descriptions, authors, and localized/English category names. World, style, battle and type filters combine; shared-world entries match either world. Style and battle filters inspect the single mode or the catalog's populated modes, and are cleared only for statistics. Results sort by type, actual update time or name, render in batches of 30, and retain search, sort, loaded rows, focus and scroll when returning from details. Mobile filters fold beside the search field; the controls stay above the independently scrolling results. Five external language packs provide the new labels.
