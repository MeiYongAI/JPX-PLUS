# 配置导入场景与卡顿排查 — 2026-11-08

基线为 2026.11.08.7（7b43fa6），本轮修复版本为 2026.11.08.8。测试使用隔离桌面 Chrome、合成战斗 DOM 和拦截的网络；未操作真实账号，没有安装到用户的脚本管理器。

## 结论

两个导入入口的含义不同：

- **配置管理器 → 导入**：读文件、命名、保存副本不替换当前策略，也不主动暂停或启动战斗。点击“应用”才更新目标世界的规则；当前世界应用战斗策略会先暂停。统计配置和另一个世界的配置不改变当前战斗的运行状态。
- **基本设置／战斗规则页底部 → 导入**：原生配置直接成为当前未保存编辑。本轮改为先完整校验、准备所有模式，再暂停战斗并替换运行规则；支持撤销／重做，点击“保存”才写入原生配置。此入口读取原生配置，不把配置管理器的封装格式当作原生配置。
- **统计设置页底部 → 导入**：先校验版本和字段，再更新统计编辑；不改变战斗规则和自动状态，仍需保存才持久化。

这些操作的 JSON 解析、校验、存储和界面更新仍运行于页面主线程，因此大型配置或较大的配置库可能造成一次性停顿。之前的功能回归只能证明结果正确，不能据此断言导入过程不卡顿。本轮单独加入了性能测量。

## 已修复问题

1. **应用大配置时，变更标记重复匹配规则。** 新保存基线与运行对象没有共享内部身份，3,000 条规则需要 4,501,500 次数组查找谓词访问，出现平方级增长。现对已确认相等的应用部分直接传递内部身份，不再逐条扫描之前的规则。其他未保存草稿的基线保持不变，重复规则、排序标记与空容器兼容性均有回归。
2. **文件读取乱序覆盖。** 两次选择文件，较早文件最后读取完成时会覆盖较新的命名表单。现用导入操作代次保证只有当前选择可提交界面结果。
3. **离开管理页面后迟到导入接管界面。** 切换标签、关闭设置、页面替换后，旧文件仍可能继续解析并改变管理器状态。现检查操作代次、页面、节点连接和销毁状态；过期文件和错误结果不再替换新界面，也不继续执行无用校验。
4. **旧入口遇到坏配置时部分修改仍然生效。** 以前逐模式直接写入运行对象，后面的坏规则抛错时前面的模式已经改变；成功导入也没有暂停。现在复用配置库校验，保留旧版本字段和规则迁移，全部准备成功后才暂停和替换。坏文件、自定义代码被拒绝、读取失败均保持原数据。
5. **旧入口同样存在异步过期和版本漏检。** 加入操作代次、标签／对话框状态检查、2 MiB 文件限制及取消选文件处理；统计配置缺失、过旧或非数字版本不再显示成功或污染当前版本号。
6. **已有大量规则时再次导入，变更标记仍然重复扫描。** 3,000 条相同规则需 4,501,500 次匹配访问，全部修改后需 9,000,000 次；排序标记还重复调用 indexOf。现在先按规范化内容建立候选索引、再以原有相等判断确认，排序位置直接查询 Map。保留对象键顺序无关、重复规则互不冒领身份、空容器兼容、显式快捷键分组和改动标记语义。

配置管理器保留导入／应用分离，旧入口加强校验；战斗 Stop 的手动恢复语义保持不变。

## 性能对照

每种场景、每个入口、每个版本均创建独立上下文测量 3 次，新旧版本交替执行；表中为 3 次中位数，单位 ms。战斗夹具持续生成日志更新，生产监听与决策正常运行。配置管理器在应用后生效并暂停；旧入口在导入后立即更新未保存编辑，新版会暂停（基线版不暂停）。

| 合成场景 | 文件大小 | 新版解析／校验／命名表单 | 新版保存／列表刷新 | 旧版应用 | 新版应用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 20 条规则 | 2,523 B | 4.5 | 6.4 | 15.4 | 15.5 |

| 500 条规则，另有 40 份各 100 条的配置 | 56,203 B | 10.2 | 41.4 | 62.4 | 59.5 |

大规则应用场景明显改善，但仍观察到长任务；拥有较多存档时，库序列化和校验仍有明显成本。小配置场景未观察到长任务，不应把这一结果外推到手机或复杂真实配置。

重复导入已修改的大规则，导入阶段由约 1.42 秒缩短到 93 ms。首次导入的旧代码缺少完整校验；新版补齐校验和暂停后阶段耗时上升，不能宣称所有场景都加速。相同规则的阶段计时与长任务方向也不同：基线在异步读文件之前及观察器回调中还有变更标记扫描，阶段计时不涵盖全部工作，应同时看长任务。长任务数据说明大文件依然可能有可见停顿。

测量不计文件选择器等待、文件读取 I/O、自动化等待；阶段包括脚本同步操作与相关界面更新，浏览器长任务记录可能包含该阶段之外的同一任务开销（包括之后的 MutationObserver）。旧入口不必要的选文件前历史快照已去掉；选文件前的独立任务未计入表中。计时包装本身也存在少量开销。它们不是实战 TPS，也不是每回合增加的固定耗时。

## 剩余边界

- 大配置应用仍可能短暂阻塞。若后续要继续削减，应单独处理配置库序列化与验证的重复成本，不能通过跳过验证来换性能。
- 没有验证所有真实策略规则的持续执行成本；复杂条件或自定义代码可能影响每回合，而保存一份未应用的配置不会直接进入规则执行循环。
- 网络、脚本管理器沙箱、真实文件系统、移动设备和其他插件的交互，需在相应环境另测。
