# 主站 / alt 共享数据

版本：2026.11.08.12。

## 使用方式

更新同一份 JPX-PLUS 主脚本后，先关闭仍运行旧版本的 HV 页面，再依次打开主站和 alt 的非战斗页面。第一次访问某个站点时，脚本保留其旧配置快照，并把旧战斗历史加入共用存档。未打开的站点，其原生站点存储不能被另一站点直接读取。

共享范围是同一浏览器配置文件、同一油猴脚本安装实例中的主站与 alt。不是跨设备云服务，不上传到 GitHub，也不修改 HVUT 或汉化脚本的存储。主世界与异世界仍独立记账。

配置、快捷键、配置库及应用选择、统计设置、主题与体力读数使用脚本管理器 GM 存储作为唯一持久化来源。没有在两个站点各写一套配置再互相覆盖。通知只用于使页面缓存失效；读操作可复用内存缓存，无轮询。

历史战斗记录也直接读写同一共享存档。原生 IndexedDB 仅作为迁移源保留。新增结算以“世界 + 原有战斗时间戳”标识，每场保存一条收据；不同场次不通过“读整库—改整库”提交。归档导入/替换/删除使用独立操作，删除历史不会返还已消耗体力。

**正在进行的战斗原始日志、逐回合临时状态和页面识别缓存仍是站点本地数据。** 本版本修复已结算历史及配置、体力账本的共享；不承诺在战斗中从主站切换到 alt 后无缝续接原始日志或临时计数。不要同时在两站操控同一世界的同一场战斗。旧版时间戳只有秒级精度，不具备服务器提供的战斗唯一 ID。

## 已有配置冲突

首先访问的站点为已有键提供初始值；后访问站点不会静默覆盖。两个站点的原始配置快照都可以在 **设置 → 统计设置 → 数据 → 主站 / alt 共享数据** 下载或选用。

共享后的修改按站点和配置键保留最近的前后版本，避免每次编辑都永久复制整份配置库。两个站点并发修改时，GM 最后写入值生效，两站各自的版本均保留在恢复入口；这不是合并编辑器，也不承诺 GM 提供跨标签事务或比较交换。恢复已有备份会暂停自动战斗。其它站点修改当前世界的执行配置也会暂停；单纯重命名未应用的配置不会暂停。

## 体力迁移

旧版只保存“当天累计体力消耗”，没有逐场完整消耗收据。两站历史可能重叠，也可能完全不同，无法从这两个汇总自动恢复精确并集。

因此迁移暂取当日两站汇总的较大值，并明确展示说明。可在同一共享数据区修改 **今天启用共享前已消耗体力（UTC）**，填入自己确认的总消耗。新版本完成的战斗另行逐场累计，不需要把它们再加入这个基数。UTC 换日后使用新的日期账本，两个世界各自有基数。

新增战斗的历史与体力放在同一收据中，失败不产生半条扣费；重复提交同一记录不再次累计。不同场次的每日免费额度按确定的完成顺序分配，历史页面读取时统一计算收益。每天的体力查询只读取当日收据，不读取整份历史载荷。

## 清理与恢复

“清除全部 JPX-PLUS 数据”会清除两个站点共用的数据，确认框额外说明这一点。保留迁移完成标记和重置标记，避免另一站仍存在的旧 IndexedDB 自动重新导入。没有改动配置商店的登录凭据。
