# 未开启 AJAX 的过轮／过层排查 — 2026-11-08

基线 2026.11.08.8（e19d627），本轮修复版本 2026.11.08.9。

本轮专门覆盖新的浏览器 document 与 JavaScript 上下文：点击模拟的原生下一轮入口，真实导航、执行 beforeunload、保留同源 localStorage，再加载脚本并调用完整 initDo。网络响应是离线合成页面，没有操作真实账号、安装中的脚本或真实游戏动作。

## 已确认并修复

1. **等待导航时重复触发下一轮。** 非 AJAX 下隐藏了下一轮按钮，但后续 goNext 没有检查隐藏状态；连续三次更新会调用原生处理器三次。现在已隐藏的过轮入口不再次自动点击。手动下一轮、暂停、最终结算不会被这个改动自动启动。
2. **首次识别读取尚未恢复的冷却统计。** initJpxModeDetection 早于 timeRecords 恢复，原先用 getActionCooldowns 提取技能名，遇到冷却中的技能会访问尚未创建的 lastUse，并被识别层吞掉异常。改为直接读取原生技能提示中的名称，保留原生文本后备；职业识别不再依赖统计初始化顺序。
3. **每个新页面重复扫描。** 启动时冷却扫描从 3 次降为 1 次；普通启动的日志 HTML 读取从 4 次降为 1 次。一个同步快照供战斗类型、轮次、怪物及初次状态解析使用；之后的日志更新和 AJAX 换轮重新读取，不跨轮保留快照。
4. **旧怪物数据跨轮复用。** 原生过轮可能早于节流的日志回调，导致旧 monsterData 还留在存储；新轮缺少怪物日志时会把旧 ID／最大 HP 当作新怪物。现在轮末离页时清除，检测轮号变化时再次失效；同一轮手动刷新仍保留可用数据。重复初始化同一日志也不再重复追加怪物条目。
5. **快速离页漏记最后动作。** 日志 MutationObserver 尚未运行，或 200 ms 节流的尾调用尚未执行时，beforeunload 只会保存旧统计。现在消费尚未交付的 mutation、取消待处理尾调用，只记录最后待处理日志，再保存。不调用 preRender、战斗决策或导航；重复保存不会再记一次。

## 性能测量方法

scripts/profile-reload.cjs 对比两版本，3 种场景，每场景重复 3 次、每次连续导航 5 轮，总计 90 个新页面样本。每轮检查统计保持、怪物 ID、轮号、楼层、职业以及未自动攻击。

下表为每个场景／版本 15 个样本合并后的中位数，单位 ms：

| 场景 | .8 初始化 | .9 初始化 | .8／.9 日志读取 | .8／.9 冷却扫描 |
| --- | ---: | ---: | ---: | ---: |
| 普通轮次，100 行日志 | 23.9 | 9.2 | 4／1 | 3／1 |
| 长日志，2,000 行 | 27.2 | 11.0 | 4／1 | 3／1 |
| 本地 40 份各 100 条规则的配置 | 32.1 | 18.4 | 4／1 | 3／1 |

较大的配置库仍会提高每个新页面首次校验成本；本轮没有用未经验证的跨页面缓存来绕过它。

统计的是同步 initDo 初始化耗时，包含存储恢复、状态识别和初次界面处理；不包含服务器等待、浏览器加载文档、脚本解析／编译、其他脚本或资源加载。不能据此当作完整过轮耗时或实战 TPS。夹具页面资源仍由拦截器返回。

原始结果 `docs/performance/reload-2026-11-08.json` 仅保存在本地，不再随仓库发布；其中保存测量源码 SHA-256、阶段耗时、读写次数和相关长任务。

复跑：

    $env:PLAYWRIGHT_CHANNEL = 'chrome'
    $env:JPX_PERF_BASELINE = 'C:/path/to/2026.11.08.8.user.js'
    $env:JPX_RELOAD_REPEATS = '3'
    $env:JPX_RELOAD_ROUNDS = '5'

## 剩余边界

- 未开 AJAX 时，服务器响应、整页解析、图片和其他脚本重新加载仍然存在。本轮只减少 JPX-PLUS 自身的重复工作。
- 大配置库依然需要在新 document 首次使用时校验；没有跨页面缓存整个库或跳过校验。
- 全页刷新产生的原生悬停事件、脚本管理器注入时序、第三方插件以及真实移动设备需要对应环境再测；本轮未安装更新到脚本管理器，也没有实战验证。
- 离页补记只消费尚未处理的日志，不试图重新构造服务器未返回或游戏已移除的历史动作。
